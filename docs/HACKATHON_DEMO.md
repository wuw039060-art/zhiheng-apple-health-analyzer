# 黑客松展示手册

## 一句话介绍

知衡健康是一款隐私优先的 Windows 桌面应用：它在本机流式解析 Apple 健康导出，用个人基线和跨指标证据，把分散的手表读数整理成可解释的趋势报告。

## 解决的问题

Apple 健康导出包含大量 XML、ECG 和运动记录，但普通用户难以回答三个问题：

1. 最近真正发生了什么变化？
2. 单个异常是否和睡眠、活动或其他生命体征同步？
3. 这个结论来自哪些数据，可信到什么程度？

知衡健康不尝试“诊断疾病”，而是补上从原始数据到趋势沟通之间的解释层。

## 三分钟演示流程

### 0:00–0:30：问题

展示 Apple 健康 ZIP，并说明原始导出不适合持续阅读。强调健康数据不应该为了获得解释而被迫上传到第三方云端。

### 0:30–1:10：导入

将测试 ZIP 拖入应用，指出：

- Rust 在本机流式解析，不把完整 XML 放进内存；
- ZIP 先经过路径穿越、符号链接、展开体积和压缩比检查；
- 再次导入相同快照不会重复累计记录。

### 1:10–2:10：解释

依次展示：

- “每日”：今日结论与睡眠、恢复、活动三大支柱；
- “洞察”：多指标证据、可能解释、把握度和限制；
- 日期与周期切换：7/30/90/180/365 天；
- “数据”：来源、覆盖、缺失、CSV 导出和删除控制。

### 2:10–2:40：差异化

强调三点：

1. 不是固定人群阈值，而是个人滚动基线；
2. 不是单点告警，而是睡眠/锻炼时间上下文中的交叉验证；
3. 不是黑盒分数，每项贡献、缺失和医学边界都可以展开查看。

### 2:40–3:00：收尾

回到隐私：没有账号、上传接口或遥测。用一句话结束：

> 知衡健康不替用户下诊断，而是让用户带着更完整、更可追溯的趋势去理解自己，并在需要时更有效地与专业人员沟通。

## 建议准备的展示材料

- 一份专门为演示构造、不含真实个人信息的 Apple 健康测试 ZIP；
- 2–3 张使用合成数据的应用截图；
- 已安装的 `v1.3.2`，避免现场等待 Rust/Node 构建；
- 安装包 SHA-256 与 GitHub Release 页面；
- 无网络备用方案：安装包已内置 WebView2 离线运行时。

严禁将真实参赛者健康 ZIP、数据库、ECG 文件或包含姓名/出生日期的截图提交到仓库或演示资料。

## 评委常见问题

### 为什么不直接做网页？

健康导出可能很大，并且包含高度敏感信息。Tauri/Rust 允许本机文件访问、流式解析、SQLite 存储和离线打包，同时保留 React 的界面开发效率。

### 如何避免重复导入？

后端为记录生成稳定指纹，并在 SQLite 事务中增量写入；重复快照只更新导入摘要，不重复累计相同健康记录。

### 如何减少健康误导？

系统要求足够的数据覆盖，以个人中位数和 MAD/IQR 建立基线；缺失数据不补值，单次读数不升级成诊断，结论必须显示证据、限制和行动边界。

### 是否使用 AI 生成医学判断？

当前核心分析是本地、确定性的规则与统计计算，没有把健康数据发送给云端大模型。这样更容易审查、复现和约束医疗表达。

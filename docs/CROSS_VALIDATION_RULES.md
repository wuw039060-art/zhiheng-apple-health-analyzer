# 多指标交叉验证规则

## 原则

1. **先确认设备事实**：事件类型、发生日期、持续时间、是否与睡眠或锻炼重叠、数据覆盖是否足够。
2. **只和同日数据交叉**：心率事件不会拿去和别的日期的生命体征拼接。
3. **个人基线优先**：每一天只使用该日之前最多 28 个完整日，避免未来数据泄漏；少于 7 日不推断偏离。
4. **组合信号高于孤立读数**：单项偏离只作趋势展示；同日两项以上偏离才生成生命体征组合提示。
5. **解释不是诊断**：输出“较吻合 / 可能 / 需补充信息”，同时显示支持证据、缺失信息和传感器限制。

## 个人典型范围

对每个指标计算最近 28 个完整日的中位数和 MAD（中位数绝对偏差）：

`半径 = max(2.5 × 1.4826 × MAD, 指标最小容差)`

最小容差用于避免稳定数据因微小噪声频繁报警：静息心率 5 次/分、HRV 7ms、呼吸频率 1.5 次/分、血氧 1.5 个百分点、腕温 0.3°C、睡眠 0.75 小时。

这是一套透明的本地趋势算法，不复刻 Apple 未公开的 Vitals 私有算法，也不是临床参考范围。

## 规则矩阵

| 主事件 | 同日支持证据 | 可能解释 | 软件动作 |
|---|---|---|---|
| 高心率 | 血氧趋势下移 + 呼吸频率上移 | 呼吸相关负担需要排查 | 提高优先级，建议结合症状和连续性就医评估 |
| 高心率 | 腕温上移 + 静息心率或呼吸上移 | 急性生理压力、疾病、酒精、海拔、药物等 | 标为“可能”，要求用户补记背景 |
| 高心率 | 睡眠短 + HRV 下移 | 睡眠不足或恢复压力 | 展示恢复证据，不确定具体诱因 |
| 高心率 | 同日 ECG 非“窦性心律”或节律通知 | 心律记录需复核 | 保留原始 ECG，建议医生确认 |
| 低心率 | 80% 以上事件与睡眠重叠，呼吸/血氧稳定 | 睡眠期生理性减慢可能 | 降低提示级别，继续观察趋势 |
| 低心率 | 睡眠重叠 + 血氧趋势下移或呼吸上移 | 睡眠呼吸问题可能 | 结合打鼾、憋醒、晨起头痛、白天嗜睡评估 |
| 低心率 | 多数发生在清醒期 | 体能、药物、甲状腺、电解质或传导问题等均可能 | 要求症状/药物背景，反复发生时就医 |
| 任意一天 | 两项以上夜间生命体征偏离 | 身体状态或测量条件发生变化 | 生成该日独立卡片，最多展示最近 5 天 |

## 不自动推断的内容

- 不凭 Apple Watch 血氧诊断低氧血症；
- 不凭腕温判断发热；
- 不凭 HRV 单项判断压力、感染或“恢复差”；
- 不凭心率阈值判断具体心动过速/心动过缓类型；
- 不把 ECG 的“无法判定”当作确诊异常；
- 不根据缺失数据默认“正常”。

## 紧急症状门槛

被动手表数据本身不会自动给出急救结论。若用户同时出现胸痛或胸部压迫感、严重呼吸困难、晕厥/接近晕厥、明显意识改变或卒中征象，界面提示立即联系当地急救；中国大陆可拨打 120。
